## Rules for these contracts

- **`triage.md`** is prose that the triage agent writes beside `triage.json`. It is not a
  contract, and it stays with `write_file`. List it in the stage's `"also"`.
- **Long text fields** (task bodies in `decomposition.json`, the issue body in triage
  `improve.json`) are string parameters. Put `maxLength` in the schema only where the gate
  enforces a length today.
- **`decomposition.json` and the task queue.** `decompose_gate`, `improve_gate` and
  `next_task` are several hundred bytes of `jq`, and `ops/test-task-gates.sh` tests them
  closely (AGENTS.md). Move only the shape checks into the schema. Do not change the queue
  logic in this task. Every existing queue fixture must still pass with a `_io` block added.
- **`fix_result.json`'s `risk`** is enforced in `fix_gate` (AGENTS.md). It becomes `required`
  in the schema, and the gate keeps its check. Both are required: the gate check is the one
  that AGENTS.md documents.
- **Triage** is imported by `arch-review` and `issue-triage`. Check both `workflow.toml`
  files after `generate`.

## Verification

For each contract, on five runs: the contract carries `_io`; the gate's repair rate for that
contract is 0 or no higher than the baseline; there is no new `human_rescue` or
`mark_needs_human` visit caused by a receipt. When all eight are live, count the
`*_attempts` counters that no longer have a shape branch. Record in the overview which
counters remain, and why each remains.

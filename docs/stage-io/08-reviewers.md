## For each stage, one commit

1. Write the schema from the gate's shape checks (`verdict`, `standards`, `spec`,
   `quality`). The two `standards` stages and the two `spec` stages may share a schema only
   if their gates check the same shape today. Compare them. If they differ, keep two schemas,
   and do not make them the same in this task.
2. Manifest: inputs in the prompt's order, `"live": true`, generate.
3. Prompt: the "Inputs" table becomes a call to `inputs` with one sentence that names what it
   returns. The output section becomes a call to `submit`. Keep every rule of judgement.
   Remove each shape rule that the schema now enforces. Keep the repository-file reading
   instructions: `inputs` covers `/tmp/fabro`, not the checkout.
4. Gate: C7's receipt check inside the existing repair branch. Remove the shape checks that
   the schema covers. Keep the semantic checks, for example "every `error` finding cites a
   rule and a `file:line`", or `risk` in `fix_gate` (AGENTS.md).
5. `ops/test-task-gates.sh`: fixtures generated by the binary, the five cases of task 07's
   list adapted to the gate, and one case for each semantic check that stays.
6. The node that runs before the agent deletes the contract file (AGENTS.md). Check that
   it still does.

`review_merge.standards` and `review_merge.spec` run in both `backlog` and `pr-review`. The
generator writes them into both `workflow.toml` files. Check both after `generate`.

## Verification

For each stage, after its push, on five runs: the first tool call is `mcp__io__inputs`; the
contract carries `_io`; the gate's repair rate is no higher than the task 01 baseline for
that stage; `lead_turns` is 1 or less at the median.

# Invariants: the review-and-merge phase

Read before changing `_shared/review-merge/` (imported by `backlog` and `pr-review`), its report hooks, or the auto-merge switches.

Every rule here passes `fabro validate` and fails at runtime, usually silently. Each one cost a live incident or was found before it could. Moved verbatim from `AGENTS.md` on 2026-10-09; the area files are siblings of this one.

## Queue mode

| Rule | What happens otherwise |
|---|---|
| Only `report_queued` adds `merge-on-green`, and only after its approval-marker comment posted | A label without a marker is handed off by the queue; the order (comment, then label) makes a failure between them leave a safe, visible PR. |
| `rm_setup` removes `merge-on-green` on every entry to the phase | A second review of a PR that is already queued would leave the old approval live while the new one runs. |
| `/tmp/fabro/merge_mode` is `queue` only when the importing graph wrote exactly that | Anything else is `watch`; `pr-review` and `dependabot` never write it. |

## The merge decision

| Rule | What happens otherwise |
|---|---|
| `risk` is gate-enforced in `fix_gate`, not merely documented | Without the check the field is optional in practice, PRs quietly stop auto-merging, and the report still says "complete". |
| Any merge-phase node that fails into `mark_needs_human` writes **both** `merge_block_reason` and `needs_human_reason` | The two renderers read different files: `blocked` reads the first, `needs-human` the second, and `mark_needs_human` renders `needs-human`. A reason written to only one of them leaves the other holding whatever a previous stage left there — on #386 that was a placeholder `validate` writes on its SUCCESS path, so the comment said the run stopped before the review was delivered while the same comment listed all three verdicts. A placeholder describing a stopping point the run went on to pass is a false statement waiting to be printed. |
| `mark_needs_human` derives the reason for a stage that FAILED into it from `failure_signature` (`stdin_source`), and prefixes a transient failure `retryable:` | A failed agent node (`standards`, `spec`, `review_fix`, a 15m timeout, a provider error) writes no reason, so the PR was labelled `ai-review-needs-human` with `unspecified` (issue #19). The node writes `"<stage> failed (<class>)"` to both reason files when the stage is an agent node, the class is `transient_infra`, or no reason file exists, so a reason left by an earlier stage is never reused for those; a deterministic failure of a command node keeps whatever reason file exists (the node's own, or a leftover: command nodes must write their reason before they fail); `transient_infra` (timeouts, provider errors) gets the `retryable: ` prefix the PR shepherd (#31) reads. A command node that wrote its own reason keeps it, and a gate routed on success (empty signature) keeps the gate's. Checked by `ops/check-graph-invariants.py` R9, which only confirms the sink reads `failure_signature` and writes both files, not that the logic is right; covered by `ops/test-task-gates.sh`. |
| Every merge-phase command node's unconditional edge lands on `mark_needs_human`; expected blocks are the *conditional* edges | A broken merge — a token without `contents: write`, an API 5xx — otherwise lands in the same quiet "not auto-merged" bucket as a risk-4 PR and stays invisible. |
| A PR labelled `do-not-merge` is never auto-merged: `merge_gate` check 2b blocks on the label, and the `merge-queue` guard hands the PR off. `architecture` no longer holds a PR (ADR 0012 D8 amendment, gate-relief G2). `open_pr` still copies `architecture` to the PR and `file_remainder` to the Remainder issue, for the scorecard | A human who wants to hold a PR has no brake the gates respect. Check 2b fails closed on a `gh` error. Covered by `ops/test-task-gates.sh`. |
| The diff-hygiene counters read `.fabro/hygiene.json` from `origin/<base>`, never from the PR head, and `config_changed` counts a PR that touches `.fabro/hygiene.json`, `.fabro/test.toml` or `.fabro/ci.sh` | A PR that could edit the rules that judge it would loosen them: raise `erosion_threshold`, drop a test path, and pass its own check. A PR that edits `.fabro/test.toml` or `.fabro/ci.sh` changes what `run_tests` and `ci.sh` execute for its own tests, so it is held the same way (ADR 0018 D7). Nothing overrides a hygiene block (ADR 0013 D2): the override is a human merge. The counters' patterns, the `config_changed` grep's `[.]fabro/` included, are bracket expressions (`[.]`, `[(]`) because `\"` is the only backslash a `.fabro` file may hold, and they run under **mawk**. The fixtures in `ops/test-task-gates.sh` are their contract. `merge_gate` check 13b refuses a HEAD whose **tree** differs from the one the counters read (the SHA always differs: every checkpoint commit is `--allow-empty`), because `refute` is an agent with write access between `hygiene` and `deliver`. |
| `ci_fix_gate` runs `/tmp/fabro/hygiene.sh` again before it pushes, and `hygiene` is the only node that writes that file | `ci_fix` changes code after `merge_gate` has approved the diff, and a CI fixer is the stage most likely to skip a failing test. A second copy of the counter program in `ci_fix_gate` would drift from the first (ADR 0013 D3). |
| `refute` sees no other agent's output, `refute_gate` computes its verdict, and a missing verdict blocks | The Refuter's value is independence: a prompt that hands it `standards.json`, `spec.json` or `fix_result.json` turns it into a fourth reviewer that agrees with the other three. An agent-written `verdict` key is ignored. The verdict is `pass` only when every criterion is `met` and there is no defect. A timed-out Refuter goes straight to `deliver`, and check 14 blocks on the absent `refute_verdict` rather than letting a provider outage through. `.refute` needs a rule in the stylesheet of **every** importing graph. Since `9c76544` it runs on `gpt-6.1-sol` (openai), a family unlike the coder's and the reviewers' (ADR 0013 D6), with `openai:gpt-6-luna` as the fallback in every importing `workflow.toml`; that fallback must never be GLM. |
| `refute_fix_attempts` is written once, to 1, when `refute_gate` takes the fix route, and nothing resets it in the run; `refute_prep` must not delete it | A second fix turn could run, so a fix and a refute could loop. The counter is set before the fixer runs, so a crashed fixer cannot loop either (ADR 0013 D5 amendment, gate-relief G8). Covered by `ops/test-task-gates.sh`. |
| Both of `refute_fix`'s outcomes go to `refute_fix_gate`, and a turn with no valid receipt is reset to `refute_fix_base` (the HEAD `refute_gate` recorded when it took the route) before the run goes to `deliver` | `deliver` pushes HEAD. A failed or timed-out fixer leaves partial edits that the checkpoint commits and `validate` never ran, so the PR would carry them under a verdict about the old tree. The gate's fixtures run in a throwaway repo: run in this checkout, the reset wipes the working tree. Covered by `ops/test-task-gates.sh` (real git). |
| `refute_fix` cannot read `refute.json`, `refute_verdict`, `refute_reason.txt` or `hygiene.json`, and `refute` cannot read `refute_fix.json` or `refute_findings.json` | The fixer could argue with the verdict, and the Refuter could judge its own change through the fixer's account, so the second verdict would not be independent (gate-relief G7). The guard is `io-guard`, matched by `(^\|[.])refute(_fix)?$` in all three importers; it is a guardrail against mistakes, not a security boundary. Covered by `ops/test-task-gates.sh`. |
| A `## Post-deploy checks` section is cut from each linked issue before `refute_issues.json` is written; its checklist goes to `post_deploy.md`, the report and the PR body, never to the Refuter | The Refuter would judge criteria that only a deployed environment can check, and block the merge on them (ADR 0013 D4 amendment). An issue with no such section is written byte-for-byte as before. The PR body's checklist sits after the commit-body block, so the commit message never carries it. Covered by `ops/test-task-gates.sh`. |

## Merging

| Rule | What happens otherwise |
|---|---|
| The merge node re-reads PR `state` from GitHub immediately before merging | The bridge's double-fire marker is per-run and does not stop a second review fired by hand. Two runs reach `merge`; the loser must report "already handled", not fail. |
| The `merge` node waits for `mergeable` to leave `UNKNOWN` and retries a branch-moved rejection | Any push to the head just before `merge` causes this. Until ADR 0011 D1 that was fabro's own checkpoint push (commit + push after every stage); since D1 neither graph pushes checkpoints, so it is now a push by `ci_fix_gate` or `remerge_base`, or by someone outside the run. The push invalidates GitHub's computed merge ref, and a merge attempted before it is recomputed is rejected as `Base branch was modified` even though the base has not moved. A pure race: `jelly-swipe#386` lost it, with the push ~15ms before `merge` started, with `main` unmoved for 35h and no protection rules, while run `01M2TFEHPYXXTQST6VPXREA854` won it with the same 10ms gap. Without the wait and the retry a mergeable PR is reported to a human as a permissions or conflict problem. |
| `gh pr merge` never passes `--delete-branch` (the merge node passes `--delete-branch=false`) | It deletes the **local** head branch as well as the remote one, and the merge is not the run's last stage: fabro's checkpoint publishes the run branch after every later stage, so the next publish fails with `src refspec … does not match any`, retries three times, and reports `failed/publish_failed`. A run whose PR merged and whose issue closed is then recorded as a failure — cost run `01M2TFEHPYXXTQST6VPXREA854` its status on 2026-09-18, eight seconds after PR #1206 merged. Reaping is `fabro-branch-sweep.sh`'s job. |
| Commit-body markers are `:start` / `:end`, never `<!-- /fabro:commit-body -->` | A closing marker with a slash forces `\/` into the extraction pattern, and `\"` is the only backslash a `.fabro` file may contain. |
| The subject is the live PR title; the body comes from the marker block | `release-please` turns an agent's `feat:`/`fix:` subject into a release on `jelly-swipe`/`lawncare-saas`, and the derivation never emits `!` or `BREAKING CHANGE:`. |

## Auto-merge kill switches

| Rule | What happens otherwise |
|---|---|
| Both auto-merge switches fail closed on a value that is **present and not exactly the enabled one** — empty, `false`, `0`, `TRUE`, malformed. **Absence is not that case**: an absent per-repo `auto_merge` token means **on** (decision 10), and an absent `FABRO_AUTO_MERGE` variable means no run is created at all | A `gh` call that returns nothing, or a broken injection read as "not disabled", merges an unreviewed PR into `main`. On `lawncare-saas` that is also a deploy. The inverse error is just as costly: reading "fails closed" as "an untouched row is disarmed" is wrong — an untouched `pr-review-<repo>` row is **armed**, and three of the four are untouched. |
| The `FABRO_AUTO_MERGE` server variable must exist | An unset `{{ vars.X }}` fails the RunIntent at compile time, so no `pr-review` run is created at all. `provision-server-state.sh` creates it; `off` writes `0` and never deletes. |
| `POST /variables` upserts, so `provision_variable` is create-if-absent | A re-provision that POSTs unconditionally silently re-arms a switch an operator killed mid-incident. It reports drift instead. |

## Reporting

| Rule | What happens otherwise |
|---|---|
| Every terminal report of the imported `review_merge` phase has a `checkpoint_saved` hook in the graph that owns the run | A blocked or merged run is silent for that report. Checked by `ops/check-graph-invariants.py` R7.
| `mark_needs_human` pushes the run's review commits when `deliver` never ran and the PR is still OPEN, and `/tmp/fabro/delivery` decides what the comment says | The comment lists `review_fix`'s edits under "Fixes applied" whether or not they reached the branch, so a human merges a PR without them (issue #8, PR #1438). With the marker, the comment says "NOT pushed" when the push was skipped (PR closed or merged, or a `gh` error) and "pushed on stop" when it succeeded. A marker `deliver` already set is never overwritten, so a refused lease is not retried. Nothing is pushed when HEAD's tree still equals `review_entry_tree`, which `rm_setup` records (marker `unchanged`): in `pr-review` HEAD carries `rebase_check`'s rebase, possibly agent-resolved, and a stop before any review edit (a reviewer timeout, an oversized diff) must not force-push it unreviewed onto the author's branch. `deliver`'s refused push reads the PR state and counts the commits the branch lacks (issue #9). Covered by `ops/test-task-gates.sh` (real git). |
| A terminal node of the merge phase publishes `merge_block_reason` and prints only its routing object | The run's events show that a merge stopped, but not why, so a recheck reads `gh` for every block (16 PR comments on 2026-10-09) and the stop is invisible when `gh` fails. Each node sends its `gh` output and warnings to `/tmp/fabro/report.log`, and fabro scans stdout and stderr for objects, so a brace on any other line can make the routing object invalid and the key silently missing. `report_blocked`, `mark_needs_human` and pr-review's `entry_failed` do this; the reason is one line, cut to 300 bytes. `ops/test-task-gates.sh`, *outcome keys*, runs each node with `gh` stubbed, including one that prints braces and fails. ADR 0020, #13. |

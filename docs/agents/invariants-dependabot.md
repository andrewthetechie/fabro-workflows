# Invariants: the dependabot package

Read before changing `.fabro/workflows/dependabot/`, its prompt, or the `dependabot-<repo>` rows. The package is ADR 0022; its task series is `docs/dependabot/`. The graph, prompt and hooks must also satisfy `invariants-graph.md` and `invariants-merge.md`.

Every rule here passes `fabro validate` and fails at runtime, usually silently. Most are checked offline by `ops/test-task-gates.sh` (the *dependabot* sections) or `ops/check-graph-invariants.py`.

| Rule | What happens otherwise |
|---|---|
| The merge loop validates in the run's own checkout, and every command node ends on the run branch with a clean tree. `dep_next` asserts it on every visit, and `dep_validate` asserts it after the restore (ADR 0022 D20, rule 4) | The patch path starts from a foreign tree, and the next checkpoint commits the PR's files as the run's work. |
| The inner validation `timeout` (1020 s) is below the node's 20 minutes, and every node's timeout is below `stall_timeout` (60 m) | The watchdog kills a node mid-merge, which leaves the tree foreign and the run without a summary. Checked by `check-graph-invariants.py` R2. |
| `dep_validate` passes the merge identity (`noreply@fabro.sh`) on the merge only, and never on `git commit` elsewhere | The plain `fabro-python` image has no git identity, so the merge fails with "Committer identity unknown" (spike S6). The identity is the one `merge_gate` expects, so `sync_base`'s merge commit matches it. |
| `sync_base` merges `origin/<base>` into the run branch before the patch, and records `sync_base_sha` | The patch cannot see the Dependabot PRs merged earlier in the run, and `patch_gate`'s diff against the base is unreliable. |
| The shared review-and-merge phase is spliced unchanged (ADR 0022 D1). A change to `_shared/review-merge/` is a change to every importing graph | The patch is judged by a phase that differs from the one `backlog` and `pr-review` use. `git diff --stat .fabro/workflows/_shared/` must be empty for this package's commits. |
| `match.jq` includes `version.jq`, and the comparator exists only in `version.jq` | Two copies of the comparator can disagree. A false match closes a PR (C5 `replaces`), and the patch gate's version check then passes a patch that does not fix the alert. |
| The tracking issue is found only by the first-line marker `<!-- fabro:dep-group key=<key> -->` (C6) | A title search finds the wrong issue, or two issues for one group. `startswith` is exact because the marker ends in ` -->`. |
| `patch` is not a git exception: the stage carries no `"git": "write"` (rule 3). Its edits are checkpointed by the run | The agent can switch branches or commit under the run's checkpoint, and `sync_base_sha` stops describing the base. |
| The per-repository switch is read once, in `prep`, from the `dependabot-<repo>` row. The merge phase reads `auto_merge_repo` that `prep` wrote, and `pr_handoff` does not re-read the row | A flip between two nodes splits one run: some PRs merge and the patch PR does not, with no record of why. |
| Every command node's deliberate failure goes through `stop`, which writes `stop_reason`, and every command node's unconditional edge goes to `summarize` (D24) | A run ends silently at the failed node, and the summary says nothing. `summarize` reads `stopped_at` and `stop_reason` to name the node. |
| Each class used by a node of the imported phase has a rule in this graph's stylesheet. `.merge-fix` is on glm-5.3-flash by D14, where pr-review has glm-5.3 | A class inherits `*`, so a merge-phase reviewer runs on the default model without a failure. Checked by `check-graph-invariants.py` R3. |
| `io-guard` and the three report hooks match the imported node ids with `(^|[.])`, and the Refuter's `io-guard` is anchored to `refute` | An unanchored matcher is silent, or it fires on the wrong node. The `io-guard` hook is in this package only because the Refuter is imported; R5 rejects it without the import. |
| `open_pr` takes the patch's labels and the `Resolves #N` line from the group. `pick_group` and `prep` delete the phase's outcome file (`review_merge_outcome`) before the phase can write one | A stale outcome from an earlier visit is read as this run's result, and the summary reports a merge that did not happen. |
| Dependabot PRs are merged by `gh pr merge --squash --delete-branch=false --match-head-commit`, and the head is re-read first | A PR that moved between the check and the merge is merged unvalidated. `--delete-branch=false` keeps the local run branch, as in the merge phase. |
| The schedules are created enabled, and `ops/provision-server-state.sh` reports drift on the `auto_merge` token but never rewrites it | A switch flipped off during an incident is restored by a re-provision, which re-arms the merge path without anyone choosing it. |

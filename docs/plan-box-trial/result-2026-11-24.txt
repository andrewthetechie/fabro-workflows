Box-plan trial — result, 2026-11-24
===================================

Question (00-overview.md): does the planner belong on a hosted model or on the run's own
coder box? The trial re-opened the question ADR 0030 closed on 2026-10-21 in favour of
hosted glm-5.3, and its answer reverses that decision (ADR 0034 D5).

Window: 2026-10-28 to 2026-11-24, UTC, inclusive dates; a run is in the window by its
dispatch time. Closed by the operator on 2026-11-24 (ralph-v2 E19), before task 03 of that
series made the box the only arm in both stylesheets.

VERDICT: the box wins. `plan` runs on the run's own leased box in `backlog` and `ralph`,
`.plan` is one stylesheet line in each, and the `plan` stage's manifest `box` is `true`
(ADR 0034 D5). The evidence is the merge numbers below.

The arm rule
------------
One rule in both stylesheets (`backlog/workflow.fabro`, `ralph/workflow.fabro`), written as
a template conditional on the run's issue number:

    (issue_number // 2) % 2 == 1   the run's leased box, coder_pool, medium (both graphs)
    (issue_number // 2) % 2 == 0   backlog: glm-5.3
                                   ralph:   kimi-k3 and its fallback chain

Not parity: `SCHEDULER_RALPH_SHARE` already sends even issues to `ralph`, so bit 1 splits
each lane's own numbers in half. An unbound `issue_number` (a hand fire without one) reads 0
and planned hosted. The arm is visible after the fact as the `plan` stage's model in fabro's
usage, and before the fact with `fabro preflight -I issue_number=N`. Nothing else differed
between the arms: the same prompt, the same contract, and the same gates.

The merge numbers
-----------------
`ralph` issue runs, from the scheduler's run history joined to each run's PR facts, box arm
against hosted arm:

    | ralph issue runs       | box arm, merged | hosted arm, merged |
    |------------------------|-----------------|--------------------|
    | 2026-11-02 to 11-12    | 16 of 61 (26%)  | 25 of 66 (38%)     |
    | 2026-11-12 to 11-24    | 50 of 97 (52%)  | 44 of 87 (51%)     |

The rows begin 2026-11-02, the day `SCHEDULER_RALPH_SHARE` went to 100 and `ralph` stopped
sharing the queue with `backlog`; the trial's first five days are in neither row. The second
row is also the window the evidence in `docs/plans/ralph-v2/` was read over.

Which window is read
--------------------
The two windows disagree, and the later one is read.

- 2026-11-02 to 11-12 puts the box arm 11.6 points behind (26% against 38%). With 61 and 66
  runs the standard error on that gap is 8.2 points, so the gap is 1.4 standard errors: it
  cannot separate the arms at the two-standard-error bar the factory reads results with.
- 2026-11-12 to 11-24 puts the box arm 1.0 point ahead (52% against 51%). With 97 and 87 runs
  the standard error is 7.4 points, so the gap is 0.1 standard errors: the arms are level,
  and that is the reading the close rests on.

The earlier window's counts are kept here for the record, not read against the box arm.

The verdict, by the trial's own rule
------------------------------------
The trial's rule (00-overview.md, *Decision*): "The box arm wins if its merge rate is no
worse and its coder and rework minutes per task are no worse by more than their week-to-week
noise. If it wins, the box planner's credit saving decides it". This record holds the merge
rate, and `ralph`'s runs only: the minutes per task and `backlog`'s two arms are not in it.

The later window's merge rate is no worse — 52% against 51%, level inside the noise — so on
it the credit saving decides, and it is the box's. The planner was the largest z.ai charge
the factory had: in the week the quota ran out (2026-10-22..27) `backlog`'s `plan` on
glm-5.3 was 22% of all credits, and `ralph`'s `plan` added 6.7% through its kimi-k3
fallback. A box planner spends no credit at all, and it spends the lease that is already
bought for the run.

What the close changed
----------------------
- Both stylesheets: the `{% if %}` arm block is one `.plan` line on the run's box, so every
  `plan` visit in either workflow is a box visit.
- Both manifests: the `plan` stage's `box` is `true`. The `"plan-arm"` value itself stays in
  the generator, the checker, `fabro-io` and the scheduler, because finished runs and old
  images still carry it.
- Timeouts are unchanged (ralph 80m, backlog 60m). Each is still the 2026-11-11 two-slot
  doubling, and neither is measured on the box.
- `ops/scheduler`'s planner report still groups by the arm bit. For a run dispatched after
  this close reached `main` that bit is not an arm; a run dispatched between the decision
  and the push still carries one.

Recorded in ADR 0034 D5, which reverses ADR 0030 D1. The graphs' comments above `plan` carry
the numbers that matter to the node.
